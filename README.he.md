# 🐜 נמלה (Nemla) — פלטפורמה קלה לסיור ברשת, מודיעין שירותים ואבטחה דפנסיבית

**גילוי · סריקה · זיהוי שירותים · הערכה · דוחות · ניטור**

[English](README.md) · [العربية](README.ar.md) · **עברית**

נמלה (בערבית: **نملة**) היא פלטפורמה קטנה לסיור ברשת, כתובה ב-Python **וללא תלויות חובה**. תנו לה כתובת IP (גרסה 4 או 6), שם אתר, טווח או רשת שלמה, והיא תמצא מכשירים פעילים, תסרוק פורטי TCP ו-UDP, תזהה את השירות שמאחורי כל פורט פתוח (מוצר, גרסה, תעודת TLS, פרטי פרוטוקול), תנחש את מערכת ההפעלה ממספר אותות בלתי תלויים, ותהפוך את מה שראתה ל**ממצאים מבוססי ראיות** עם רמת ביטחון ודרך תיקון. היא כותבת דוחות ב-**HTML, JSON, CSV, Markdown ו-SARIF**, זוכרת את הסריקות שלכם ואומרת מה השתנה, ויכולה לשמור על רשת מפני פעילות חשודה. הכול זמין **בעברית, בערבית ובאנגלית**: בשורת הפקודה, בדוחות ובממשק אינטרנט תלת־ממדי.

## מה חדש בגרסה 2.0

- **ארכיטקטורה אמיתית.** קובץ `nemla.py` היחיד (1,900 שורות) הפך לחבילה `nemla/`: יעדים, גילוי, מתזמן מוגבל, סורקי TCP ו-UDP, תוסף קטן לכל פרוטוקול, זיהוי מערכת הפעלה, ממצאים, דוחות, היסטוריה ושמירה. `python3 nemla.py ...` ו-`import nemla` ממשיכים לעבוד. ראו [docs/architecture.md](docs/architecture.md).
- **IPv6** בכל מקום (יעדים, סריקה, גילוי, דוחות, היסטוריה, הממשק).
- **סריקת UDP** עם מצבים כנים: `open`, `closed`, `open|filtered`, `unknown`, בקצב מוגבל ובאופן בטוח.
- **זיהוי שירותים כתוספים:** HTTP/HTTPS, SSH (כולל האלגוריתמים שהשרת מציע), FTP, SMTP, POP3, IMAP, DNS, Redis, Memcached, MySQL/MariaDB, PostgreSQL, RDP (עם NLA), SMB (SMBv1 וחתימה), Telnet, VNC, וכן ניתוח TLS ותעודות עם קורא X.509 משלנו.
- **ביטחון בכל מקום.** כל תוצאת שירות או מערכת כוללת רמת ביטחון והראיות שלה. ניחוש מהמספר של הפורט בלבד מסומן כניחוש.
- **מנוע ממצאים שמראה את העבודה שלו:** מזהה, חומרה, כותרת, תיאור, ראיה, מארח, פורט, תיקון וביטחון, בשלוש שפות.
- **דוחות:** תקציר מנהלים, נתוני הסריקה, שגיאות ואזהרות, וכן Markdown ו-SARIF 2.1.0.
- **דיוק ומהירות:** אפשרויות מאומתות, מתזמן שאינו צובר עשרות אלפי משימות, מגבלות כלליות ולכל מארח, הגבלת קצב, תקציב בדיקות וביטול שנכנס לתוקף בתוך עשירית שנייה.
- **הקשחת אבטחה** של השרת המקומי, הדוחות, ההיסטוריה וה-launcher, עם בדיקה לכל תיקון. ראו [אבטחה](#אבטחה).

## למה נמלה?

[nmap](https://nmap.org) חזק בהרבה, ומומלץ להשתמש בו לעבודה רצינית. נמלה נועדה לרגעים שבהם רוצים משהו קטן ומסביר יותר:

- **בלי התקנה**: ספרייה סטנדרטית של Python בלבד (Scapy אופציונלית). בלי חלקים מקומפלים.
- **היא מסבירה את עצמה.** כל ממצא אומר מה נצפה, כמה נמלה בטוחה ומה לעשות.
- **ביטחון כן.** נמלה לא מציגה ניחוש כעובדה.
- **דוח שאפשר למסור**: דף HTML כהה וקריא, או Markdown ו-SARIF לכלים שלכם.
- **עברית וערבית**: `--lang he` או `--lang ar` מחליפים את שורת הפקודה, הדוחות והממשק, כולל כיווניות מימין לשמאל.
- **קוד קריא**: Python פשוט, מודול קטן לכל פרוטוקול. מצוין ללמוד איך סורקים עובדים.

## התחלה מהירה

</div>

```bash
# רשת שלמה, הפורטים הנפוצים
sudo python3 nemla.py -t 192.168.1.0/24

# מארח אחד, פורטים 1-1000, וגם פורטי ה-UDP הנפוצים
python3 nemla.py -t 192.168.1.10 -p 1-1000 --udp

# IPv6, וכמה יעדים יחד
python3 nemla.py -t 2001:db8::5,192.168.1.10-20

# כל פורמטי הדוחות
python3 nemla.py -t 192.168.1.10 --json scan.json --csv scan.csv --md scan.md --sarif scan.sarif

# סריקה עדינה: 50 חיבורים בשנייה, ולכל היותר 5,000 בדיקות
python3 nemla.py -t 192.168.1.0/24 --rate 50 --max-probes 5000

# ממשק ודוח בעברית או בערבית
python3 nemla.py -t 192.168.1.10 --lang he

# לשימוש ב-CI: קוד יציאה 3 על כל ממצא חמור
python3 nemla.py -t 10.0.0.0/24 --fail-on high
```

<div dir="rtl">

`sudo` נחוץ רק בשביל Scapy (בקשות ARP אמיתיות, ICMP גולמי, טביעת אצבע SYN). בלעדיו נמלה קוראת את טבלת השכנים של מערכת ההפעלה וחוזרת לפקודת `ping` ולחיבורים רגילים.

## אפשרויות

| אפשרות | תיאור |
| --- | --- |
| `-t`, `--target` | IP, שם, CIDR, `10.0.0.1-50`, `10.0.0.1-10.0.0.50`, IPv6; כמה יעדים מופרדים בפסיקים |
| `-4` / `-6` | פתרון שמות ל-IPv4 או ל-IPv6 בלבד (ברירת מחדל: כתובת ה-IPv4 הראשונה, אחרת ה-IPv6 הראשונה) |
| `--all-addresses` | סריקת כל כתובת שהשם נפתר אליה |
| `-p`, `--ports` | `22`, `22,80,443`, `1-1000` או שילוב |
| `--top-ports` | לסרוק גם את רשימת הפורטים הנפוצים (ברירת המחדל כשאין `-p`) |
| `--udp` | לסרוק גם את פורטי ה-UDP הנפוצים |
| `--udp-ports LIST` | פורטי UDP לסריקה (מפעיל את `--udp`) |
| `--udp-timeout S` / `--udp-rate PPS` | המתנה לכל בדיקת UDP (ברירת מחדל 1.0) / חבילות בשנייה (ברירת מחדל 200) |
| `-o`, `--output` | נתיב דוח ה-HTML (ברירת מחדל `nemla_report.html`) |
| `--json`, `--csv`, `--md`, `--sarif FILE` | לכתוב גם את התוצאות בפורמט הזה |
| `--no-ping` | לדלג על גילוי מכשירים ולהניח שכל היעדים פעילים |
| `--no-os` | לדלג על זיהוי מערכת הפעלה |
| `--no-banner` | לדלג על קריאת באנרים וזיהוי שירותים |
| `--intensity 0-9` | מאמץ זיהוי השירותים: 0 כלום, 5 ברירת מחדל, 9 מנסה כל פרוטוקול |
| `--threads N` | המגבלה הכללית של בדיקות מקביליות (ברירת מחדל 150, מקסימום 2000) |
| `--per-host N` | מגבלת בדיקות מקביליות על מארח אחד (ברירת מחדל 100) |
| `--timeout S` | זמן קצוב לחיבור TCP בשניות, גדול מ-0 (ברירת מחדל 0.7) |
| `--rate PPS` | הגבלת ניסיונות חיבור TCP בשנייה (ברירת מחדל ללא הגבלה) |
| `--max-probes N` | לעצור אחרי N חיבורים/חבילות בסך הכול (ברירת מחדל ללא הגבלה) |
| `--max-hosts N` | לסרב ליעדים גדולים מ-N כתובות (ברירת מחדל 1024, המגבלה העליונה כמיליון) |
| `--fail-on LEVEL` | קוד יציאה 3 אם יש ממצא ברמה `low`, `medium` או `high` ומעלה |
| `--watch INTERVAL` / `--watch-log FILE` | סריקה חוזרת כל `90s`, `15m` או `2h` ודיווח על שינויים |
| `--diff OLD.json NEW.json` / `--fail-on-change` | השוואת שתי סריקות שמורות; קוד 3 אם הופיע משהו חדש |
| `--guard`, `--guard-ports`, `--guard-interval`, `--guard-log` | ניטור דפנסיבי (בהמשך) |
| `--lang en\|ar\|he` | שפת שורת הפקודה, הדוחות והממשק |
| `-v`, `--verbose` | פרטי דיבוג ל-stderr |
| `--ui`, `--ui-port`, `--no-browser`, `--keep-alive` | הממשק התלת־ממדי |
| `--install-launcher` / `--uninstall-launcher` | פריט בתפריט היישומים של לינוקס |

קודי יציאה: `0` הצלחה, `1` שגיאה (יעד לא תקין, דוח שלא נכתב), `2` ארגומנטים שגויים, `3` ממצאים ברמת `--fail-on` ומעלה (או שינויים עם `--fail-on-change`).

## איך זה עובד

</div>

```
יעדים -> גילוי -> מתזמן מוגבל -> סריקת TCP / UDP
      -> זיהוי שירותים -> זיהוי מערכת הפעלה -> ממצאים -> דוחות
```

<div dir="rtl">

1. **יעדים** הופכים למקטעי מספרים שלמים שמפיקים כתובת אחת בכל פעם (IPv4 ו-IPv6). פורטים נקראים אחרי שכל גבול נבדק.
2. **גילוי** מתחיל ב-ARP ברשתות IPv4 פרטיות, ואז בודק בעזרת ICMP ו-TCP כל כתובת ש-ARP לא ענה עליה; מכשירים שנמצאו כך מקבלים כתובת MAC מטבלת השכנים. אין סומכים על ARP שהוא שלם, ואזהרה אומרת מתי הוא לא היה.
3. **המתזמן** שולף משימות בהדרגה, אוכף את המגבלה הכללית, את המגבלה לכל מארח, את הקצב ואת התקציב, ועוצר הכול בתוך עשירית שנייה כשלוחצים Stop או Ctrl+C. מארחים נסרקים זה לצד זה וכל אחד מסתיים ברגע שהמשימות שלו נגמרו.
4. **זיהוי שירותים** קודם קורא מה שהשרת אומר מעצמו, אחר כך שואל שאלות ייעודיות לכל פרוטוקול (תוסף לכל פרוטוקול), מנסה TLS כשזה סביר ומביט בתוך המנהרה. שום דבר לא מתחבר עם משתמש ושום דבר לא משנה מצב.
5. **זיהוי מערכת הפעלה** אוסף קולות משוקללים מ-TTL, מ-SYN-ACK (חלון, אפשרויות, DF), מבאנרים, מפורטים פתוחים, מעובדות פרוטוקול ומיצרן כרטיס הרשת, ושומר את הראיות.
6. **ממצאים** עולים רק על מה שנצפה. מספר פורט בלבד נותן ממצא בביטחון נמוך יותר ובחומרה נמוכה בדרגה, ומסומן ככזה.
7. **דוחות** נבנים מאותם נתונים בכל שפה.

### ביטחון

לכל תוצאת שירות או מערכת יש `confidence` (מ-0 עד 1) ודגל `heuristic`. באנר שמציין מוצר וגרסה מקבל כ-0.95, תשובת פרוטוקול תקינה בלי גרסה כ-0.85, ומספר פורט בלבד 0.3 (`heuristic: true`). ניחוש מערכת ההפעלה מוגבל ל-0.70 כשהוא נשען על הסקה בלבד ול-0.92 כששירות נקב במערכת בעצמו, כי בעל המכשיר יכול לערוך באנרים. שום דבר לא מוצג כודאי.

### ממצאים

לכל ממצא יש `id`, `severity`, `title`, `description`, `evidence`, `host`, `port`, `proto`, `remediation` ו-`confidence`. דוגמאות:

| ממצא | עולה כשנמלה ראתה | חומרה |
| --- | --- | --- |
| `telnet`, `ftp`, `mail_plain`, `smtp_plain_auth`, `basic_auth_plain` | שירות או התחברות בטקסט גלוי ברשת | בינונית עד גבוהה |
| `redis_open`, `memcached`, `es_open` | תשובה ל-PING / `version` / `GET /` ללא אימות | גבוהה |
| `smb1`, `smb_signing` | משא ומתן SMBv1 התקבל; חתימה לא נדרשת | גבוהה / בינונית |
| `rdp_no_nla`, `rdp_weak_security` | שרת ה-RDP קיבל הפעלה ללא NLA / עם אבטחה ישנה | בינונית / גבוהה |
| `tls_expired`, `tls_expiring`, `tls_not_yet_valid` | תאריכי התעודה | גבוהה / בינונית |
| `tls_old`, `tls_weak_sig`, `tls_weak_key`, `tls_selfsigned` | לחיצת יד TLS 1.0/1.1 הושלמה; חתימת SHA-1/MD5; RSA מתחת ל-2048 ביט; נושא שווה למנפיק | בינונית / נמוכה |
| `ssh_protocol1`, `ssh_weak_crypto` | באנר SSH-1; אלגוריתמים חלשים בהצעת החלפת המפתחות | גבוהה / בינונית / נמוכה |
| `snmp_default`, `tftp`, `udp_exposed` | SNMP ענה ל-`public`; TFTP ענה; שירות UDP שניתן להחזרה בכתובת ציבורית | בינונית עד גבוהה |
| `dns_recursion` | דגל RA בתשובת DNS (פותר פתוח הוא רק אפשרות) | נמוכה עד בינונית |
| `admin_panel`, `remote`, `db`, `files` | קונסולת ניהול, גישה מרחוק, מסד נתונים או שיתוף קבצים נגישים | נמוכה עד גבוהה |
| `http_plain` | נסרקו פורטי HTTP **וגם** HTTPS ואף אחד לא מגיש TLS (לעולם לא אחרי סריקת פורט 80 בלבד) | נמוכה |

חשיפה בכתובת ציבורית (נקבעת לפי `is_global`, ולכן מרחב כתובות משותף וטווחי תיעוד לא נחשבים) מדורגת חמורה יותר מרשת פרטית. הממצאים מתארים חשיפה והגדרות חלשות, לא פרצות ניתנות לניצול: נמלה לא משווה גרסאות למסד CVE ולא מנסה להתחבר או לנצל דבר.

## דוחות

`--json` הוא הרשומה המלאה (גרסת סכמה 2) והוא מה שההיסטוריה שומרת. הוא שומר כל שדה מהפלט של 1.x. ה-CSV שומר קודם את העמודות של 1.x (`ip,mac,vendor,os_guess,ttl,port,service,banner,product,version`) ומוסיף `proto,state,confidence,os_confidence`; תאים שעלולים לרוץ כנוסחאות גיליון מנוטרלים. Markdown מנטרל כל דבר שהגיע מהרשת. ול-SARIF 2.1.0 יש כלל לכל מזהה ממצא ותוצאה לכל ממצא, עם המארח והפורט כמיקום, לשימוש עם GitHub code scanning, DefectDojo ולוחות דומים.

## מה השתנה מאז הפעם הקודמת

נמלה זוכרת את הסריקות שלכם (60 האחרונות, בתיקיית הנתונים של נמלה, לכל אחת UUID אקראי) ומשווה כל סריקה חדשה לקודמת של אותו יעד: מכשירים שהופיעו או נעלמו, פורטים שנפתחו או נסגרו (TCP ו-UDP), שירותים שהמוצר, הגרסה או הפרוטוקול שלהם השתנו, משפחת מערכת הפעלה שונה, וממצאים שהופיעו או נפתרו.

## מצב שמירה (דפנסיבי)

נמלה יכולה גם לצפות ברשת במקום לסרוק אותה:

- **פורטי פיתיון.** פורטים שאין לשום מכשיר לגיטימי סיבה לגעת בהם (כברירת מחדל 2222, 2323, 5901, 8888 ו-3307). כל מה שמתחבר אליהם בודק את הרשת שלכם.
- **מכשירים לא מוכרים.** הבדיקה הראשונה לומדת את המכשירים שלכם לפי כתובת MAC; מכשיר שלא היה שם קודם מעלה התראה (עם שם היצרן כשידוע).
- **שינויי ARP.** כתובת שעונה פתאום ממכשיר אחר.

להתראות השמירה יש **רמת ביטחון והראיות** שמאחוריה. שינוי בקישור ARP **אינו** הוכחה להתחזות: החלפת כרטיס רשת, שינוי DHCP או מכונה וירטואלית נראים אותו דבר, ולכן נמלה שוקלת אם הכתובת היא שער הרשת, כמה פעמים הקישור מתהפך, אם הכתובת החדשה שייכת למכשיר מוכר ואם הישנה עדיין עונה, ולעולם לא עוברת את 0.85. השמירה רק צופה: היא לא תוקפת בחזרה, לא סורקת מכשירים אחרים ולא משנה את חומת האש (למכשיר שרוצים לחסום היא מדפיסה את הפקודה המדויקת ומשאירה לכם להריץ אותה).

## אבטחה

נמלה סורקת רשתות עוינות ומציגה את מה שזרים כתבו, ולכן היא מוקשחת בהתאם. לכל סעיף להלן יש בדיקות.

- **השרת המקומי:** מאזין ל-`127.0.0.1` בלבד; אסימון אקראי לכל הפעלה (בכותרת לכתיבה, בכתובת לקריאה); בדיקות `Host`, `Origin` ו-`Sec-Fetch-Site` (נגד DNS rebinding ובקשות מאתרים אחרים); תקרה לגודל הבקשה; זמנים קצובים לחיבורים סרק; תקרה לחיבורים ולזרמי אירועים; מדיניות Content-Security-Policy קפדנית; שום traceback לא יוצא מהשרת; פרמטרי הסריקה מאומתים ומוגבלים; והסריקה הראשונה דורשת אישור.
- **באנרים ותעודות זדוניים:** כל קריאה מוגבלת בגודל ובזמן; טקסט מהרשת מנוקה מתווי בקרה, מקודי מסוף ומהיפוך כיווניות לפני שהוא נרשם או נשמר; קורא תעודות ה-DER נבדק בקלטים אקראיים וזורק סוג שגיאה אחד בלבד; הדף מצייר עם `textContent`, והדוחות מנטרלים כל שדה (ישויות HTML, הגנת נוסחאות ב-CSV, ישויות Markdown).
- **מיצוי משאבים:** טווחי פורטים עוינים (`1-99999999999`) נדחים לפני שהם מורחבים; יעד של מיליון כתובות הוא כמה מספרים; המתזמן שולף משימות בהדרגה; JSON מקונן עמוק נדחה; קובצי ההיסטוריה מוגבלים בגודל.
- **מערכת קבצים:** קובצי היסטוריה ודוחות נכתבים לקובץ זמני ומועברים למקומם (בהרשאות פרטיות); המזהים הם UUID שמאומתים לפני שהם נוגעים בנתיב; קבצים סטטיים לא יכולים לצאת מתיקיית האינטרנט.
- **פקודות:** בלי shell בשום מקום; ל-`ping` מגיעות רק כתובות מאומתות; ה-launcher בלינוקס מצטט כל נתיב.
- **מרוצים:** שפת הסריקה היא לכל תהליכון (בלי החלפה גלובלית), והמונים נעולים.
- **פענוח לא בטוח:** רק `json.loads` על נתונים לא מהימנים; בלי pickle, eval או exec (בדיקה סורקת את הקוד אחריהם).
- **SSRF:** בדיקות לא עוקבות אחרי הפניות או כתובות שנמצאו באנרים; היעד הוא רק מה שהקלדתם.

## מה דורש הרשאות מוגברות

שום דבר מהנדרש לסריקה רגילה. סריקת חיבור, זיהוי שירותים וניתוח TLS, בדיקות UDP, IPv6, דוחות, היסטוריה, קריאת טבלת השכנים
ומצב השמירה משתמשים בשקעים רגילים ורצים כמשתמש רגיל בלינוקס ובווינדוס. שתי תוספות אופציונליות בונות חבילות בעצמן: טביעת אצבע
של TCP/IP (חבילת SYN אחת וקריאת ה-SYN-ACK) ובקשות ARP ש-Scapy שולחת. שתיהן דורשות Scapy והרשאות לחבילות גולמיות (root בלינוקס,
או חלון פקודות מנהל עם Npcap בווינדוס). בלעדיהן נמלה אומרת זאת בשורה אחת, רושמת זאת באזהרות הדוח וממשיכה: ניחוש מערכת ההפעלה
נשען על TTL, באנרים ופורטים פתוחים, וביטחון נמוך יותר. נמלה אינה מבקשת הרשאות מוגברות ואינה מעלה אותן בעצמה. פרטים ב-
[docs/privileges.md](docs/privileges.md).

## IPv6 וגילוי שכנים

יעדי IPv6 נתמכים במלואם: כתובות מפורשות (`::1`, `2001:db8::5`, `[::1]`, `fe80::1%eth0`) וטווחים קטנים, סריקות TCP ו-UDP, דוחות,
היסטוריה והשוואה. **תחיליות גדולות נדחות ולעולם לא מורחבות**: `/64` הן 2^64 כתובות, ולכן כל מה שמעל מגבלת המארחים
(`--max-hosts`, לכל היותר 1,048,576) נדחה לפני שנבנתה כתובת אחת. ב-IPv6 אין שידור ואין ARP, ולכן **מארח IPv6 לא מוכר ברשת
המקומית אי אפשר למצוא בסריקת טווח** כמו ב-IPv4: נמלה בודקת את הכתובות שנתתם לה (ICMP ו-TCP) ואינה מגלה זרים. כדי למצוא שכני
IPv6 השתמשו בטבלת השכנים של הראוטר או ב-`ip -6 neigh` וסרקו את הכתובות. גילוי ARP ובדיקות ה-ARP של מצב השמירה הם ל-IPv4 בלבד.

## מגבלות

- TCP היא סריקת חיבור (בלי סריקת SYN). תשובות UDP מובנות רק לפרוטוקולים שלמעלה; `open|filtered` נפוץ ב-UDP, ולינוקס מגבילה תשובות ICMP, ולכן סריקה מהירה של מארח לינוקס מדווחת על הרבה פורטים סגורים כך.
- הממצאים מתארים חשיפה והגדרות, לא פרצות ניתנות לניצול. אין התאמת CVE.
- זיהוי מערכת ההפעלה הוא הערכה ממספר אותות חלשים. טביעת האצבע של TCP דורשת Scapy ו-root, והצורות שלה הן המתועדות בהרחבה, לא מסד נתונים מלא.
- בדיקות SMB ו-RDP עוקבות אחרי הפרוטוקולים המפורסמים אך נבדקו מול שרתי בדיקה, לא מול כל גרסת Windows אמיתית; התייחסו לממצאים שלהן כרמזים לאימות.
- גילוי שכנים לא מוכרים ב-IPv6 לא מבוצע: תנו כתובות או טווחים מפורשים.
- חומות אש ששומטות חבילות גורמות למכשירים להיראות כבויים. נסו `--no-ping` ו-`--timeout` גדול יותר. ב-Windows חיבור שנדחה מדווח אחרי כשתי שניות.

## שימוש אחראי

**סרקו רק מערכות ורשתות שבבעלותכם או שיש לכם אישור כתוב מפורש לבדוק.** סריקה ללא אישור עלולה להפר חוקים, תנאי ספקים ומדיניות ארגונית. נמלה היא כלי סיור: היא מגלה ומדווחת, והיא לא מנצלת דבר. הבדיקה היחידה שקרובה לפרטי התחברות מינימלית בכוונה: SNMP נשאל פעם אחת בקהילה המוכרת `public`, ולעולם לא מנסים שום התחברות. מחבר הכלי אינו אחראי לשימוש לרעה.

## שדרוג מ-1.x

`python3 nemla.py ...` ו-`import nemla` ממשיכים לעבוד, וכל אפשרות ושדה פלט מ-1.x עדיין קיימים (נוספו שדות חדשים). שינויים שתבחינו בהם: יעדי IPv6 מתקבלים; אפשר לתת כמה יעדים יחד; מזהי הסריקות הם UUID (המזהים הישנים עדיין נטענים); `history` ו-`guard` עברו ל-`nemla.history` ול-`nemla.guard` (השמות `nemla_ui.*` עדיין מפנים לאותם מודולים); הממצא `http_plain` דורש הוכחה ש-HTTPS נסרק; ו-`--timeout 0` ומספרים לא תקינים אחרים נדחים.
